# Indicators & Work Dashboard

### Главное на неделю

В «Работе» выберите **«Главная проблема недели → Записать / уточнить»**. Вопрос: *The biggest problem of the week is…* Запишите важный разрыв, который хотите сократить. Неделя идёт с понедельника по воскресенье по Ташкенту. Прошлые недели и предыдущие формулировки доступны в карточке; новая неделя начинается с `No Data`.

Windows и Android сохраняют запись сначала на устройстве и автоматически отправляют на подключённый сервер при доступной связи. В браузере черновик хранится на устройстве, а «Сохранить» записывает его на сервер. Подробнее: [ADR-035](docs/ADR-035-weekly-problem-and-focus-layout.md), [пользовательские проверки](docs/acceptance/35-weekly-focus.feature).

Личное пространство для работы: задачи и кейсы, помидорки, ежедневные нормативы, показатели, проекты с моделером и заметки.

**Статус:** рабочая бета. Исходники клиента Windows/Android — **0.1.20**, сервер — **1.21.0**. Сборки Windows и Android опубликованы в Releases. Есть локальное сохранение и синхронизация со своим сервером. Отдельные аккаунты нескольких пользователей на одном сервере пока не реализованы.

## Попробовать

Для отдельного таймера с нормативами начни с **[Focus & Norms](FOCUS-README.md)**: собственное приложение для Windows/Android, локальная база, первый запуск без сервера и аккаунта. Есть [отдельный runbook](docs/FOCUS-RUNBOOK.md), JSON-перенос и исходники для доработки под свои потребности.

Ниже — полный дашборд.

Начни с [инструкции первого запуска](docs/QUICKSTART.md). Она рассчитана на нового пользователя и описывает цикл **работа → норматив → Play → учёт → проверка результата**.

- [Сборки Windows x64 и Android arm64 — 0.1.20](https://github.com/malikvalikhodjaev/work-productivity-tool/releases/tag/v1.21.0-native-beta.22).
- `windows-x64.zip` содержит клиент. Для его первого запуска потребуется отдельно запущенный сервер из исходников по разделу «Разработка».
- APK подключается к собственной установке сервера через HTTPS/Tailscale. Одного APK для первоначальной настройки полностью без сервера пока недостаточно.

У пробующего человека должна быть своя установка с собственными данными. Для передачи подходят опубликованные сборки. Авторский каталог `data/`, локальная SQLite и приватные ZIP переноса содержат личный архив и не входят в комплект для знакомства.

## Возможности

| Раздел | Что можно сделать |
| --- | --- |
| **Показатели** | Следить за выбранными целями, замерами, часовыми нормами и дневным планом помидорок. Неизвестные значения показываются как `No Data`. |
| **Проекты** | Вести список или доску проектов; в моделере — таблицу альф, свои столбцы, вложенность WBS, состояния, свидетельства и следующие шаги. |
| **Работа** | Создавать карточки и кейсы, писать размышления, менять стадии, отмечать проблему дня и запускать связанный таймер. |
| **Таймер** | Помидорки и секундомер, пауза, учёт минут, ежедневные нормативы, личный дневной лимит с предупреждением о завышенном плане, недельная статистика, наблюдения, темы и звуки. |
| **Письмо** | Писать форматированные заметки, добавлять избранное, удалять в корзину и разбирать входящие своего Telegram-бота. |
| **Данные** | Смотреть таблицы, очередь, состояние синхронизации и выгружать локальную копию. |

В Windows и Android используется Flutter-клиент с SQLite. У веб-версии отдельный интерфейс. Например, отдельный чистый лист `/write` пока доступен в вебе; полное совпадение всех экранов не обещается.

В темах таймера есть **«Моне · Кувшинки»**: локальная репродукция картины с затемнением под отсчётом. [Источник и лицензия](docs/ART-CREDITS.md).

## Таймер и нормативы отдельно

Уже можно начать с крупного плеера: в **Работе** включи таймер и нажми **Крупный таймер**. В нём виден дневной чек-лист; остальные разделы можно пока не осваивать.

Самостоятельная редакция **Focus & Norms 0.1.0** имеет отдельные имя, базу и Android-пакет. Первый запуск работает без сервера. Поддерживаются локальное сохранение и ручной перенос JSON; автоматическая синхронизация в этой редакции пока отсутствует. [README](FOCUS-README.md) · [Решение](docs/ADR-031-sharing-and-focus-edition.md).

## Где сохраняются данные

- **Устройство:** SQLite, локальные правки и очередь. Точный путь показан в **Данных**. На Windows каталог обычно находится в `%APPDATA%\uz.iw\Indicators & Work Dashboard`.
- **Сервер:** каталог `data/`, исходные записи, версии и резервные копии. После успешной синхронизации устройства видят общие данные одной установки.
- **Без связи:** после первоначального подключения действия сохраняются на устройстве. Автоматическая отправка выполняется при доступном сервере, пока приложение работает.
- **Резервирование:** [runbook](docs/RUNBOOK.md) описывает копии, обновление и восстановление. Локальная JSON-выгрузка и резервная копия серверного `data/` имеют разное назначение.

## Известные ограничения

- Один сервер обслуживает одного владельца. Изоляция аккаунтов для знакомых и семьи — отдельная будущая функция.
- Один общий активный таймер; другая работа не заменяет его автоматически. У отключённых устройств возможны расхождения, которые сохраняются для разбора.
- Даты норм и статистики пока считаются по **Asia/Tashkent, UTC+5**.
- Сигналы и малое Android-окно зависят от разрешений и фоновой политики телефона. Фактическое время сохраняется отдельно от доставки сигнала.
- Полные завершённые рабочие помидорки увеличивают счётчик; паузы, перерывы, отмена и досрочное завершение не дают целую помидорку.

## Разработка

Сервер использует Node.js 24 и стандартные модули Node. Для запуска из исходников:

```sh
node server.mjs
```

Локальный адрес — `http://127.0.0.1:8787`. Публичный репозиторий не содержит личного `data/`; новая установка создаёт собственный архив. Стартовые категории показателей — шаблон, их значения нужно настроить под себя.

Для проверок установи зависимости разработки:

```sh
npm ci
npm run check
npm test
```

Клиент собирается отдельно по [инструкции Flutter](native-app/README.md). Сервер можно разместить на своём ПК или VPS; удалённый доступ настраивается через закрытый шлюз Tailscale. Данные и ключи остаются вне Git.
