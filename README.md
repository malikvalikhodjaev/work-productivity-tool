## Native 0.1.5 · Фокус как Play

▶ **Фокус** на карточке работы, проблемы или норматива запускает таймер сразу с текущей длительностью и режимом. Формы «Начать фокус» и промежуточного «Сохранить» нет. ## Версия 1.2.0 · Подготовленный вариант Tailscale

**На Android ↗** в верхней панели показывает состояние подключения и установку веб-приложения на главный экран. Название установленного приложения — **Indicators & Work Dashboard**. Четыре раздела и данные остаются общими с ПК. Финансовое приложение Personal Throughput Accounting не изменяется.

ПК должен быть включён, подключён к интернету и Tailscale; сон отключает доступ. Без соединения при загрузке отображается отдельный экран. Личные данные в офлайн-кэш не записываются. Повторное подключение необходимо при изменении DNS-имени ПК/сети. Внешние аккаунты, вход и фактическая проверка через мобильную сеть не входят в автоматические тесты. Решение и ограничения: [ADR-004](docs/ADR-004-android-private-view.md).

Автозапуск можно включить отдельно командой `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-Autostart.ps1`, убрать — той же командой с `-Remove`. Это запуск после входа пользователя, а не системная служба до входа. Для нестандартного `DASHBOARD_DATA_DIR` настрой переменную постоянно в окружении пользователя перед подключением и автозапуском.

## Версия 1.1.5 · Главное на сегодня

Четыре кнопки разделов: **Показатели → Проекты → Работа → Данные**. В начале показателей видны главная работа текущего дня, проблема, следующий ход, окно фокуса и сохранённый прогресс. Независимы от выбранного периода показателей.

**Работа** — важнейший разрыв → один результат дня → следующий ход → своё окно без прерываний. Общая дата позволяет вести и прошлые дни. Работа связывается с проектом, альфой, задачей, кейсом или системой; ниже доступны три приоритетные характеристики и ограничитель связанной системы. **Учесть время** переносит дату, название и связь в запись времени. Показанные часы — фактически учтённые записи выбранного дня по этому объекту; поле окна фокуса — план.

Состояния: **Выбрано, В работе, Есть препятствие, Готово**. Процент 0–100 — собственная оценка продвижения; пустое поле означает `No Data`. Для 100% необходимо состояние «Готово» и подтверждение результата. Отметка не создаёт замеров характеристик, выполнения цели или готовности альфы. Из моделера кнопка **Главное на сегодня** подготавливает поля из сохранённого объекта; пользователь проверяет и сохраняет их во вкладке «Работа». В моделере выбранный объект показывает состояние и процент сегодняшней работы. Черновики защищены при переходе к другой дате или объекту.

Хранилища: `data/daily-results.json` и `data/daily-problems.json`, с историей прежних значений. Таблицы последних версий и CSV доступны в **Данных**. Чтение старых результатов не переписывает исходный JSON. `/api/today?date=YYYY-MM-DD` отдаёт выбранный день; `/api/daily-results` принимает дополнительно `progress`, `workRef`, `whyImportant`, `nextStep`, `focusWindow`, состояния `in_progress` и `blocked`. Сохранение защищено `expectedUpdatedAt`.

Раскрываемая подсказка опирается на присланный пост Никиты Бира, [речь Маска в USC (2014)](https://www.youtube.com/watch?v=e7Qh-vwpYH8&t=205) и **подпись** Хормози к [присланному Reels](https://www.instagram.com/reels/DcbjKtgugqp/). Звуковая дорожка ролика не расшифрована; ссылка на оригинал поста Бира не установлена. Время подъёма и длительность фокуса пользователь выбирает сам.

Три явные вкладки:

1. **Показатели** — активные цели и заданные недельные нормативы с прогрессом. Цель выбирается статусом «Активна»; пауза и архив доступны в свёрнутом списке. 3. **Данные** — исходные и локальные таблицы, нормативы, все поля объектов моделера и история их сохранений. Для сверки показаны источники файлов, даты снимков Coda и доступен CSV. Обновление перечитывает локальный сервер.

## Моделер альф

**Моделер альф:** встроен во вкладку «Проекты». Кнопка «Развернуть» открывает [отдельную страницу](http://127.0.0.1:8787/alphas); её также можно открыть через `Open-Alphas.cmd`. Последний запускает локальный сервер при необходимости. Сессия: выбрать проект и один конкретный объект → записать мысль и известные факты → следующий ход и дата возврата → сохранить. Достаточно проекта и имени объекта; остальные поля необязательны.

Новая страница редактирует **те же** проекты и объекты, что Проекты: данные в `data/dashboard.json`, справочник в существующем `data/imports/alpha-reference.json`. На основном экране — большая заметка, факт/свидетельство, ожидаемое состояние/критерий, следующий ход и возврат. Альфа, адаптированная альфа, область интересов, важность, источник/MetaU, адаптация MetaS → L0, время системы и статус внимания находятся в свёрнутых деталях. Альфа и точное состояние предлагаются из пользовательского справочника, а не из придуманного списка.

`Сохранить запись` / `Ctrl+S` атомарно пишет объект и его содержательную историю в одном JSON. Просмотр и повторное сохранение без правок не добавляют историю. На первой правке старого объекта сохраняется исходная версия. Несохранённый черновик остаётся в localStorage этого браузера; его можно восстановить после открытия объекта. Конфликт с правкой из другой вкладки отклоняется: перед обновлением страницы скопируй свой несохранённый текст. Черновик не считается сохранением в файл или выполнением нормы.

Экспорт JSON включает объекты, проекты и историю. Импорт сначала показывает проверку: добавляются отсутствующие объекты; повторный импорт их не удваивает. Отличающиеся объекты с тем же ID пропускаются, локальные записи и настройки существующих проектов сохраняются. Импорт не заменяет нормы, часы, деньги или задачи. Переносимый экспорт содержит только сохранённые записи, не черновики. Дата заполнения в отдельной свёрнутой секции добавляет карточку в прежний счётчик нормы; простая заметка автоматически не признаётся готовой альфой.

Новые локальные API: `GET /api/alphas/export`, `GET /api/alphas/history?id=...`, `POST /api/alphas/import` с `{backup, commit:false}` для проверки и `commit:true` для добавления. `updateAlpha` принимает `expectedRevision` для защиты от устаревшей записи. Внешней синхронизации, загрузки в Coda и автоматического заполнения KPI нет.

## Версия 1.1.2

В начале **Показателей** — блок **Сегодня**, всегда для текущего дня и недели в Ташкенте. Он объединяет проблему дня, один основной результат с подтверждением готовности, учтённое за день время и остатки по нормам до воскресенья. Темп = остаток по учёту / число календарных дней до воскресенья включительно. Перевыполнение одного норматива не закрывает другой; часы и количество альф считаются отдельно. Будущие записи не входят в сегодняшние итоги. Пока факта нет, показан `No Data`; остатки явно рассчитаны по имеющимся записям, полнота учёта времени неизвестна. Выбор другой недели ниже или быстрого периода не меняет **Сегодня**. **Учесть** открывает запись с сегодняшней датой и выбранным направлением.

Основной результат дня хранится в `data/daily-results.json` с историей правок и в `data/daily-results.csv`. **История → Данные → Результаты дня** показывает все даты и позволяет выгрузить CSV. Новый день начинается без выбранного результата. Отметка готовности требует подтверждения и не создаёт замеров характеристик или выполнения задач. API: `GET /api/today`, `GET /api/daily-results`, `POST /api/daily-results` с `date`, `text`, `status` (`planned`/`ready`), `evidence`, `expectedUpdatedAt`.

В начале **Показателей** есть компактная строка **Главная проблема сегодня**: дата, свободная формулировка и сохранение. По умолчанию выбрано сегодня в Ташкенте; можно открыть и исправить прошлый день. Проблема понимается как разрыв между желаемым и текущим состоянием. Подсказка помогает выбрать важнейший разрыв, включая ещё не наступившие угрозы. Записи независимы от быстрого периода и недели нормативов. Пустой день показывает `No Data`, вчерашняя формулировка автоматически не переносится.

**История** открывает **Данные → Проблема дня**, где видны все даты, последняя формулировка и число правок; таблицу можно скачать в CSV. Основное хранилище — `data/daily-problems.json`, включая прежние формулировки каждой даты. Читаемая таблица последних версий — `data/daily-problems.csv`. Одновременная правка из другой вкладки не перезаписывается молча. API: `GET /api/daily-problems`, `POST /api/daily-problems` с `date`, `text`, `expectedUpdatedAt` (для нового дня — `null`, для правки — timestamp из GET). Новые личные данные остаются локальными.

- **Время:** по нормам, по направлениям без плана, вне норм и ещё не разобранное; независимый разрез по характеру работы и детализация записей.
- **Системы:** три приоритетные характеристики и ограничитель. База, цель, факт с датой и подтверждением. Плашки видны у связанных проектов, задач, кейсов и альф.
- **Цели:** собственные замеры или общий факт характеристики системы, срок и прогресс от базы к ориентиру.
- **Кейсы:** ситуации с контекстом и следующим ходом, короткая диагностика и дата возврата.
- **Деньги:** ручные операции, импорт CSV с предпросмотром, защита от повторов и отдельные итоги по валютам. Исправления сохраняют историю.
- **Данные:** новые таблицы и CSV-выгрузки. Хранилище новых сущностей — `data/workspace.json`.

[ADR-002](docs/ADR-002-personal-work-loop.md) описывает правила, формат финансового CSV и границы первой версии. Автоматическое подключение Focus To-Do, Coda и мобильных финансовых приложений пока не реализовано.

Первый сценарий: **Проекты → Система** → задать три приоритета и предел → **Влияние / связь** у проекта или кейса → **Замер**. В **Показателях** добавь цель и записи времени. Без значений плашки показывают `No Data`.

```sh
npm start
```

Дважды нажми **Открыть дашборд.cmd**. Локальный сервер запустится в фоне, страница откроется в браузере: http://127.0.0.1:8787/.

Нужен установленный Node.js 22 или новее. Внешние пакеты и доступ к интернету для работы дашборда не нужны. После выключения компьютера снова открой этот файл. Автозапуск при входе в Windows пока не настраивался.

## Нормативы

Слева находятся кнопки разделов **Показатели**, **Проекты**, **Financial flow** и **Данные**. На узком экране они переходят в горизонтальный ряд. Вверху показателей и финансового раздела есть быстрые периоды: **Сегодня**, **7 дней**, **30 дней**, **90 дней**. Они отбирают фактические записи по календарным датам в часовом поясе Ташкента. Недельные нормативы ниже имеют собственный выбор недели и не пересчитываются как месячные цели.

В **Показателях** есть четыре компактные самооценки: распорядок дня, продуктивность и стресс, результативность, темп развития. До первого ввода они показывают `No Data`. Для каждой указан ориентир **7–8/10**; подсказка и следующий ход раскрываются по кнопке **Что улучшить**. Кнопка **Оценить** сохраняет новую оценку с датой. **Таблица оценок** сразу открывает **Данные → Самооценки**. История хранится в `data/indicators.json` и автоматически записывается также в читаемую CSV-таблицу `data/indicator-ratings.csv`. Если в выбранном периоде оценки нет, карточка показывает `No Data`, а не переносит старую оценку на новую дату.

**Проекты** показывает проекты, зоны, альфы и задачи. **Financial flow** показывает направления продажи дома и бизнеса, а также учтённые по этим направлениям часы за выбранный период. Денежные поступления, расходы и чистый поток показывают `No Data`, пока нет записей сумм; часы не превращаются в денежные показатели.

- Чтение: **10 ч/неделю**, отдельный норматив.
- Самостоятельная работа с руководствами и проектом: **10 ч/неделю**.
- Разбор с наставником: **3 ч/неделю**.
- Продажа дома, бизнес, поддержка рабочих задач, остальные нужды, домашние дела: часы задаются самостоятельно.
- Заполненные альфы: количество задаётся самостоятельно.

Кнопка **Нормативы** и карандаш на плашке открывают настройки. Пустое поле означает «не задан», ноль не используется в качестве цели. Сохранение относится к выбранной неделе. При первом открытии новой недели копируется план ближайшей ранее сохранённой недели; уже открытые недели сохраняют собственный план.

Неделя: понедельник — воскресенье, часовой пояс **Asia/Tashkent**. Записи попадают в неделю по своей календарной дате. Стрелки переключают недели, **Сегодня** возвращает текущую.

## Прогресс

**Добавить запись** позволяет вручную учесть часы или заполненные альфы. 30 минут = 0,5 часа. Одна запись относится к одному направлению. Чтение и руководства имеют независимые цели; повторно записывать одно и то же время в две категории не следует, иначе общий итог будет завышен.

Прогресс = факт / норматив × 100%. Полоса заполняется максимум до 100%, процент и факт показывают перевыполнение. Для руководств и наставника общий круг учитывает выполнение каждой цели отдельно: лишние часы самостоятельной работы не заменяют часы наставника. Альфы не складываются с часами. При незаданном нормативе учитывается факт, процент не вычисляется.

На карточках `No Data` означает, что замер или дата заполнения ещё не внесены. Это не ноль часов и не выполненный норматив. Реальные счётчики проектов и задач показывают `0`, когда объектов действительно нет. Оформление: графитовый текст, нейтральный светлый фон, белые поверхности с тонкой границей и сдержанные цветовые статусы.

Фактические часы в недельных плашках сейчас берутся из локальных записей `data/dashboard.json`; автоматического суммирования внешних часов пока нет. Скрипты извлечения копии базы Focus To-Do находятся в `scripts/`; требования к их запуску описаны в [инструкции выгрузки](docs/focus-to-do-export.md).

[ADR-001](docs/ADR-001-time-sources.md) описывает рекомендуемую связку целиком: **Coda — проекты, задачи, кейсы, шаблоны и нормативы; Focus To-Do — основной таймер; дашборд — показатели и пробелы**. Карточка Coda связывается с задачей таймера по постоянным ID. Coda Time Entries остаётся кандидатом на ручной резерв и импорт проверенной истории. ADR задаёт правила заполненности и адаптации альф, доступность с телефона, требования к загрузчику и варианты кнопки Coda. Автоматический запуск конкретного таймера Focus To-Do из Coda пока не подтверждён.

Уточнение ADR от 29 сентября: кейс может существовать вне проекта и начинаться с неполной картины. В версии 1.1 работает локальный реестр кейсов, журнал диагностик и счётчики отсутствующих и просроченных обзоров. Подключение этого реестра к Coda — отдельный этап.

Вкладка **Данные** показывает пять таблиц из локального хранилища: записи выбранной недели, историю самооценок, проекты, альфы и задачи всех проектов. Дополнительно можно подключить локальный снимок работ, целей и Issues из Coda, а также отдельный пакет альф, состояний, вопросов, ролей и рабочих ходов. Это исходный шаблон, его строки не считаются выполненными слотами проекта. Снимок хранится в `data/imports/coda-snapshot.json`, справочник — в `data/imports/alpha-reference.json`; исходный документ Coda не изменяется. Данные Coda не добавляются к локальным счётчикам часов, проектов и альф: у источника нет однозначного соответствия этим показателям. Сроки и измерения без значения показаны как `No Data`.

**Обновить** перечитывает локальные файлы, но не обращается в Coda. **Скачать CSV** сохраняет открытую таблицу на компьютер. Выгрузка не меняет исходный JSON. `GET /api/imported-data` отдаёт оба локальных снимка. Автоматическую синхронизацию Coda нужно подключить отдельно.

Данные хранятся в читаемом файле **data/dashboard.json** на этом компьютере. Они сохраняются после закрытия страницы и перезапуска сервера. Для резервной копии скопируй всю папку `data/` при остановленном сервере, включая самооценки и импортированные снимки. Пользовательские данные не добавляются в Git. Ошибка чтения существующего файла останавливает запуск, не затирая исходник.

## Следующий этап: локальный бот

Работают нормативы, недельный прогресс, карточки проектов и альф, задачи и ручной ввод. Подключение Telegram или другого источника задач пока не выполнено. Сервер уже принимает записи через локальный API. Компьютер должен быть включён, чтобы сервер и будущий бот работали.

## Проекты, зоны и слоты альф

Раздел **Проекты и альфы** позволяет создавать проекты и отслеживать их статус: активен, на паузе, закрыт. Этап проекта задаётся отдельно: до эксплуатации или в эксплуатации. Счётчики относятся к текущему состоянию проектов, а не к выбранной в соседнем разделе неделе.

В новой установке проектов, альф и задач нет. Создай первый проект во вкладке Проекты, затем добавь нужные слоты.

В карточке альфы есть типовое имя, уникальное имя объекта, описание, состояние, критерий, подтверждение и следующий шаг. Поле **Состояние по моему шаблону** сохраняет точное название из твоего шаблона. Общие состояния дашборда — рабочая шкала для подсчётов; она не подменяет состояния конкретного руководства. Подсказка по заполнению находится внизу раздела.

Отметка **Слот заполнен** с датой автоматически добавляет одну альфу в норматив соответствующей недели. Повторное сохранение той же карточки с той же датой её не удваивает. Снятие отметки исключает карточку из подсчёта. Каждая подальфа — отдельный слот. Ручные записи количества альф продолжают работать и прибавляются к карточкам: не учитывай один объект двумя способами.

Заполненный слот ещё не означает подтверждённое состояние. Зона требует внимания, если слота нет, он не заполнен, состояние не подтверждено, нет критерия или свидетельства, либо не подтверждены подальфы. Зона закрывает пробел, когда все её корневые альфы и их подальфы удовлетворяют этим условиям. Для состояния «Не применяется» требуется объяснение в подтверждении; такой объект не учитывается как заполненный слот. Свои зоны добавляются кнопкой **＋ Зона**. Зону со связанными альфами нельзя отключить, пока альфы не перенесены.

Задачу можно создать отдельно или из следующего шага карточки альфы. Счётчик **Открыто до эксплуатации** считает незакрытые задачи с этой отметкой в активных проектах. Перевод проекта в эксплуатацию не скрывает оставшиеся задачи. Кнопка слева от задачи закрывает её; повторное нажатие открывает снова. Закрытие задачи не подтверждает альфу автоматически.

При первом запуске обновления исходный JSON копируется без изменений в **data/dashboard.json.before-projects.json**. Нормативы и прежние записи сохраняются. Проекты, альфы и задачи хранятся в том же локальном JSON.

Дополнительный API: `GET /api/portfolio`; `POST /api/portfolio` принимает `action` и объект `input`. Действия: `createProject`, `updateProject`, `addZone`, `createAlpha`, `updateAlpha`, `createTask`, `setTaskDone`. Через них будущий локальный бот сможет работать с теми же карточками.

API слушает только 127.0.0.1. Его нельзя открыть с телефона или из интернета. Локальный бот может отправлять данные в него с этого же компьютера.

### API

- `GET /api/health` — проверка работы.
- `GET /api/dashboard?week=2026-09-28` — нормативы, факты и записи недели.
- `GET /api/overview?period=7d` — факты и самооценки за `today`, `7d`, `30d` или `90d`.
- `GET /api/indicator-ratings` — вся история самооценок; `POST /api/indicator-ratings` — сохранить оценку с `indicatorId`, `date`, `score` и необязательным `note`.
- `PUT /api/targets` — объект `week` и `targets` с нормативами выбранных направлений.
- `POST /api/entries` — запись с `metricId`, `date`, числом `amount`, необязательным `title`.
- `DELETE /api/entries/{id}` — удаление конкретной записи.

Изменяющие запросы используют `Content-Type: application/json`. Идентификаторы направлений: `guides`, `mentor`, `reading`, `house_sale`, `business`, `work_support`, `household`, `other`, `alphas`.

Для будущего бота передаются `source` и `externalId`: повторная загрузка одного идентификатора из того же источника возвращает уже существующую запись, не удваивая факт. Обновление уже загруженной записи пока не реализовано.

Пример полного тела запроса для задачи на 1,5 часа (пример не загружается автоматически):

```json
{
  "metricId": "guides",
  "date": "2026-09-28",
  "amount": 1.5,
  "title": "Самостоятельная работа с руководством",
  "source": "bot",
  "externalId": "task-137"
}
```

Путь к данным и порт можно изменить переменными `DASHBOARD_DATA_FILE` и `DASHBOARD_PORT` при ручном запуске `node server.mjs`.

`DASHBOARD_DATA_DIR` задаёт общий каталог для всех хранилищ, включая `workspace.json`, самооценки и импортированные снимки. `DASHBOARD_DATA_FILE` переопределяет только файл недельных записей. Не запускай два процесса на одном каталоге данных.

API версии 1.1: `GET/POST /api/workspace`, `PATCH /api/entries/{id}` для классификации, `GET /api/finance?period=7d`, `POST /api/finance/transactions`, `PATCH /api/finance/transactions/{id}`, `POST /api/finance/import` с `csv`, `source`, `commit`. При `commit: false` импорт только проверяется.

## Проверка разработки

`npm run check` проверяет синтаксис; `npm test` проверяет недельные границы, расчёты, сохранение, наследование нормативов, валидацию и защиту от повторной загрузки задач. Тесты используют отдельные временные файлы, пользовательские данные не меняются.

## Импорт таблиц

Файлы Coda необязательны: без них локальные таблицы продолжают работать, а внешние источники показывают `No Data`. Формат описан в [контракте локальных снимков](docs/import-format.md). Ошибка в существующем JSON не подменяется пустыми данными.
