# Контекст личного дашборда

Название интерфейса — **Indicators & Work Dashboard**, краткий знак — **I&W**. Это имя личного дашборда. При правках оформления сохраняй совместимость существующих ID, событий, черновиков и источников импорта.

Перед изменениями структуры дашборда, фокуса, моделера или источников данных прочитай README и относящийся к изменению ADR из `docs/`.

При выборе функций и показателей читай `docs/ADR-003-dashboard-outcomes.md`: главный приоритет владельца — собранность. Предложенные замеры продуктивности, затратности поддержки и ограничитель не считать подтверждёнными численными целями; неизвестные значения оставлять `No Data`.

Продуктивность владелец определяет через улучшение скорости и темпа создания и изменения систем с нужными характеристиками. Сохраняй это определение; календарное время до результата, результаты за период и трудозатраты имеют разные основания измерения.

## Android и доступ

Нативный клиент Windows/Android — `docs/ADR-012-native-client-and-daily-reminders.md`, исходники в `native-app/`. По запросу владельца SQLite хранит снимки пяти разделов, черновики и очередь; это расширение ограниченного браузерного хранения ADR-007. Не отправляй очередь другой установке, не перезаписывай отправленные команды, не удаляй личную базу при обновлении клиента. Дневные нормы повторяются каждый час; «Сделал» не создаёт минут. Ключ подписи APK и его пароль никогда не включать в Git. Многопользовательский доступ супруги — пока только требование ADR-013; текущий сервер остаётся с одним владельцем.

Текущий офлайн-учёт — ADR-007: по явному включению устройства IndexedDB хранит минимальный контекст работ и очередь таймера. Это разрешённое владельцем исключение к прежнему запрету локального сохранения. Не кэшировать все личные API. Один общий активный сеанс гарантируется только при связи с ПК; независимые сеансы устройства проверяются на пересечения при отправке. Офлайн-факт, исходный сеанс и постоянная квитанция пишутся атомарно в dashboard.json. Не удалять очередь до квитанции и не отправлять её автоматически другой установке.

Текущее решение владельца — `docs/ADR-006-computer-host-and-timer.md`: рабочий сервер на ПК, общий сохраняемый таймер и закрытый рабочий шлюз через Tailscale. Старые ADR-004 и ADR-005 сохраняются как история. Шлюз с явно выбранным `access: read-write` допускает запись владельца с проверкой identity, Host, Origin и маршрута; старый конфиг без access остаётся read-only. Ни редактор, ни шлюз не публиковать открытым портом; Serve направлять только на 8789. Sites остаётся прежним снимком, не рабочим источником. Перед переносом сохранить весь каталог данных и проверить, что работает один пишущий сервер. Сеанс таймера и запись факта сохраняются атомарно в одном dashboard.json; не разносить завершение по двум независимым файлам.

Следующие два абзаца описывают прежние версии доступа; при изменениях текущего маршрута использовать ADR-006.

Текущее решение — `docs/ADR-005-sites-web-view.md`: закрытый Site владельца, согласованный снимок данных в D1 и вложения в R2. Локальный ПК остаётся редактором; облако предназначено для просмотра. Не называй снимок автоматической синхронизацией. Личные файлы передаются только в runtime после подтверждения owner-private политики, никогда через исходники, Git или SQL-миграции. Служебный токен — только память/скрытый stdin. Не делай Site публичным с включённым служебным updater. `data/cloud-view.json` содержит локальную ссылку и дату снимка, остаётся игнорируемым. Установка на Android ещё требует действия владельца.

Перед изменениями удалённого доступа читай `docs/ADR-004-android-private-view.md`. Локальный редактор — только `127.0.0.1:8787`; через Tailscale Serve публикуется отдельный сервер просмотра `127.0.0.1:8789`. Сохраняй проверку аккаунта владельца и запрет записи. Не направляй удалённый прокси на редактор. Не кэшируй личные API и не коммить `data/remote-access.json`, адрес сети или аккаунт. Подготовленное PWA не означает, что фактический доступ вне домашней сети или установка на телефоне проверены.

## Источники и мысли владельца

Проблема → кейс и разделители письма — ADR-011. Сохранение проблемы автоматически обеспечивает кейс; повтор использует устойчивую связь по дате и точным совпадениям. Исходник и версии в cases[].dailyProblem; ручной контекст и состояние не переписывать. Это последовательные записи разных файлов, не общая транзакция. Delta допускает только новый embed divider:true; другие объекты и HTML по-прежнему запрещены. Логика списков/Backspace не меняется по отмене владельца. YouTube — только по действию пользователя, разрешён только проверенный iframe youtube-nocookie; не скачивать ролики и не кэшировать внешний плеер.

Окно Windows и наблюдения помидорки — ADR-010. Это окно установленного Edge/Chrome, не отдельный нативный движок. localhost сохраняет origin таймера устройства. Открытие ярлыка не меняет сеанс. Наблюдение сохраняется точно в timer.sessions[].observation атомарно с фактом и также в офлайн-очереди; старые пустые значения — No Data. Диалог привязывается к ID сеанса. Ярлыки и иконка генерируются в outputs/windows, после переноса устанавливаются снова.

Рабочая доска и фон таймера — ADR-009. Независимые работы/issues хранятся в workspace.json → workItems с ref work:UUID, заметки существующих задач и кейсов — workNotes. Сохраняй revision, requestId, исходную строку Coda и историю; не перезаписывай снимки импорта. Стадии карточки и показатели характеристик имеют отдельные основания. Legacy task.done и case.status сохраняют прежний смысл. События таймера и факт завершаются по правилам ADR-006; новым событиям записываются накопленные секунды, старым неизвестные значения не приписываются. Звук включается вручную. В офлайн-кэш входят только служебные файлы таймера и фона; доска требует сервера.

Для письма действует ADR-008: личный архив data/writing.json, Quill Delta с разрешёнными текстовыми форматами, черновики и публикации. Не исполнять HTML пользователя. Месячные счётчики считают публикации по дате записи; правки, черновики и корзина не создают новые публикации. История и корзина сохраняют исходные документы. Локальный черновик IndexedDB помогает на открытой странице; не обещать холодное открытие редактора без сети. URL личного шаблона берётся из data/writing-hints.json и references.json, не из публичного кода.

- Сохранённые ссылки, референсы и мысли находятся в `data/references.json` и показаны в **Работа → Источники и мысли**. Исходный текст — `originalText`, текущий контекст — `note`, происхождение — `origin`, прежние значения — `revisions`.
- В локальном рабочем пространстве с двумя копиями приложения личный сервер использует `../personal-dashboard/data/references.json`. При наличии `DASHBOARD_DATA_DIR` сначала проверь файл в указанном каталоге. Публичный репозиторий запускается с пустыми личными данными.
- При дальнейших изменениях возвращайся к относящимся к задаче сохранённым источникам и мыслям. Отделяй слова владельца, цитату внешнего автора и предложенное архитектурное решение. Сохранённая ссылка сама по себе не означает, что содержимое страницы проверено.
- Присланные владельцем новые ссылки и мысли добавляй в его локальную библиотеку вместе с контекстом; не создавай дубликаты. Сохраняй точные URL, включая якоря. Не придумывай отсутствующие ссылки: указывай `No Data`.
- Сохраняй исходный текст и вложения. Правки заметки должны оставлять прежние значения в истории. Используй `expectedUpdatedAt` при записи через API.
- Личные ссылки, записи, выгрузки и скриншоты остаются в игнорируемом каталоге `data/`; в Git попадают исходники и общие документы. Перед изменением существующих данных делай резервную копию.

Для дневного плана помидорок действует ADR-014: таблица pomodoroTargets в dashboard.json, ключ дата + workRef; хранить точное название пользователя. Учитывать только полные завершённые рабочие помидорки по ID сеанса, день завершения Asia/Tashkent. Паузы, перерывы, секундомер, ручные отметки и импорт часов не создают помидорки. План на вчера не переносить без явного задания новой даты. Чек-лист должен быть виден в боксе поверх, настройках и недельной статистике. Без нормы на сегодня спрашивать «Вы поставили нормативы на день?» до первого сохранённого положительного плана; отсрочка на час не отключает проверки при следующем входе/выходе. Офлайн-факт помечать, конфликтующие/исключённые сеансы не считать; версии формы и UUID команды защищают повтор и конкурирующие правки. Проверки PN01–PN08.
