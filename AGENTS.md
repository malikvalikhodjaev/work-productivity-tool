# Контекст личного дашборда

Название интерфейса — **Indicators & Work Dashboard**, краткий знак — **I&W**. Это имя личного дашборда. При правках оформления сохраняй совместимость существующих ID, событий, черновиков и источников импорта.

Перед изменениями структуры дашборда, фокуса, моделера или источников данных прочитай README и относящийся к изменению ADR из `docs/`.

При выборе функций и показателей читай `docs/ADR-003-dashboard-outcomes.md`: главный приоритет владельца — собранность. Предложенные замеры продуктивности, затратности поддержки и ограничитель не считать подтверждёнными численными целями; неизвестные значения оставлять `No Data`.

Продуктивность владелец определяет через улучшение скорости и темпа создания и изменения систем с нужными характеристиками. Сохраняй это определение; календарное время до результата, результаты за период и трудозатраты имеют разные основания измерения.

## Android и доступ

Текущее решение — `docs/ADR-005-sites-web-view.md`: закрытый Site владельца, согласованный снимок данных в D1 и вложения в R2. Локальный ПК остаётся редактором; облако предназначено для просмотра. Не называй снимок автоматической синхронизацией. Личные файлы передаются только в runtime после подтверждения owner-private политики, никогда через исходники, Git или SQL-миграции. Служебный токен — только память/скрытый stdin. Не делай Site публичным с включённым служебным updater. `data/cloud-view.json` содержит локальную ссылку и дату снимка, остаётся игнорируемым. Установка на Android ещё требует действия владельца.

Перед изменениями удалённого доступа читай `docs/ADR-004-android-private-view.md`. Локальный редактор — только `127.0.0.1:8787`; через Tailscale Serve публикуется отдельный сервер просмотра `127.0.0.1:8789`. Сохраняй проверку аккаунта владельца и запрет записи. Не направляй удалённый прокси на редактор. Не кэшируй личные API и не коммить `data/remote-access.json`, адрес сети или аккаунт. Подготовленное PWA не означает, что фактический доступ вне домашней сети или установка на телефоне проверены.

## Источники и мысли владельца

- Сохранённые ссылки, референсы и мысли находятся в `data/references.json` и показаны в **Работа → Источники и мысли**. Исходный текст — `originalText`, текущий контекст — `note`, происхождение — `origin`, прежние значения — `revisions`.
- В локальном рабочем пространстве с двумя копиями приложения личный сервер использует `../personal-dashboard/data/references.json`. При наличии `DASHBOARD_DATA_DIR` сначала проверь файл в указанном каталоге. Публичный репозиторий запускается с пустыми личными данными.
- При дальнейших изменениях возвращайся к относящимся к задаче сохранённым источникам и мыслям. Отделяй слова владельца, цитату внешнего автора и предложенное архитектурное решение. Сохранённая ссылка сама по себе не означает, что содержимое страницы проверено.
- Присланные владельцем новые ссылки и мысли добавляй в его локальную библиотеку вместе с контекстом; не создавай дубликаты. Сохраняй точные URL, включая якоря. Не придумывай отсутствующие ссылки: указывай `No Data`.
- Сохраняй исходный текст и вложения. Правки заметки должны оставлять прежние значения в истории. Используй `expectedUpdatedAt` при записи через API.
- Личные ссылки, записи, выгрузки и скриншоты остаются в игнорируемом каталоге `data/`; в Git попадают исходники и общие документы. Перед изменением существующих данных делай резервную копию.
