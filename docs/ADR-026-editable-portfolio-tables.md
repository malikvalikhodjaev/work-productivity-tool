# ADR-026 · Таблица как простой конструктор

Дата: 2026-10-18. Владелец хочет работать с таблицей по примеру Coda: открывать ячейки, столбцы и строки, самому называть столбцы. Начинаем с проектов и альф из ADR-025.

## Возможности

Нажатие на ячейку открывает редактор её значения. ↗ открывает строку карточкой со всеми полями, включая скрытые. «Строка» добавляет проект или альфу через существующую форму: для альфы сохраняется связь с проектом и зоной. «Открыть моделер» ведёт в моделирование выбранного проекта.

Свой столбец имеет UUID, название и тип: текст, число, дата, список вариантов или галочка. Название можно менять. Тип и варианты после создания сохраняются, чтобы не преобразовывать прежние значения без отдельного решения. Архив столбцов обратим: сохраняет столбец, значения и историю; восстановление возвращает их. До 100 дополнительных столбцов в каждой таблице.

Видимость, порядок и подписи стандартных полей сохраняются на устройстве. Свои названия, определения столбцов и значения синхронизируются вместе с данными. Стандартные ID и их назначение неизменны: смена подписи не меняет формулу. Счётчики заполнения и пробелов доступны для чтения.

Это первый конструктор двух существующих таблиц. Формулы пользователя, произвольные новые таблицы, связи между своими столбцами и смена типа заполненного столбца в эту версию не входят.

## Сохранение и конкуренция

В Windows/Android команда и точные before/value сначала пишутся в SQLite. У каждого изменения отдельный UUID; команды не сливаются и не переписывают отправленные пакеты. Локальная таблица накладывает очередь на снимок, в том числе созданный без сети столбец. Данные видны после перезапуска без связи. Автоматическая синхронизация использует прежнюю очередь и привязку serverId; подтверждённый снимок сохраняется перед удалением команды.

Сервер проверяет прежнее значение каждой изменяемой ячейки. Независимые поля одной строки могут объединяться; несовпадение before останавливает команду с 409, сохраняя локальный текст для разбора. Проверка сравнивает значения, а не версию каждой ячейки: изменение A → B → A отдельно не обнаруживается. Проверки связей, имён, дат и состояний моделера остаются обязательными. Изменения определения столбца проверяют revision.

Веб-редактор требует сервер. Повтор потерянного ответа использует тот же UUID команды; квитанция хранится постоянно. Открытый диалог не заменяется обновлением таблицы. Нативный незавершённый ввод ячейки сохраняется в локальном черновике с исходным before. Исходный текст, абзацы и пробелы ячеек не обрезаются. API не исполняет HTML или формулы из значений.

История ячеек — portfolio.tableHistory, столбцы — portfolio.tableColumns, значения своих полей — row.customValues. Содержательные изменения альф также входят в прежнюю историю моделера. Экспорт JSON моделера версии 1 дополнен необязательными схемой и историей таблиц; старые файлы принимаются. Импорт добавляет новые объекты, включая пустые проекты нового экспорта, и сохраняет локальные объекты при конфликте. Резервная копия всего каталога данных остаётся основной копией сервера.

## Проверка

Пользовательские сценарии CT01–CT05 — acceptance/32-editable-tables.feature. Автоматические проверки: конфликт одной ячейки и объединение разных, повтор UUID после рестарта, типы, архив/восстановление, экспорт схемы и значений, локальная очередь нескольких ячеек после рестарта, устойчивость фокуса при обновлениях репозитория. Фактический пользовательский проход на продаже дома ещё требует владельца.
