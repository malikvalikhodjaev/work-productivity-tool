# ADR-004 · Просмотр дашборда с Android из любого места

Дата: 2026-10-09. Статус: архитектурное решение реализовано в версии 1.2.0; подключение аккаунта и проверка через мобильную сеть ещё требуются.

## Запрос и характеристики

Владелец выбрал имя **Indicators & Work Dashboard** только для личного дашборда и попросил установку веб-версии на Android. На вопрос о сети ответил **«Из любого места»**. Финансовое приложение сохраняет имя Personal Throughput Accounting.

Из ADR-003: мобильный обзор должен помогать возвращаться к выбранному важному и снижать затраты на поддержку. Данные на телефоне должны совпадать с сохранёнными данными ПК; установка не создаёт второй задачник. Первая версия предназначена для просмотра. Совместное редактирование и доступ других людей не выбраны владельцем.

## Решение

1. Веб-приложение PWA: manifest, иконки 192/512, самостоятельное окно, установка из Chrome, ссылки на Показатели / Проекты / Работа. Название при установке — Indicators & Work Dashboard.
2. ПК остаётся сервером и местом хранения данных. Локальный редактор слушает только `127.0.0.1:8787`.
3. Отдельный сервер просмотра слушает только `127.0.0.1:8789`. Tailscale Serve публикует **его** по постоянному HTTPS-адресу внутри закрытой сети Tailscale. На ПК и Android требуется вход в один аккаунт и активное подключение.
4. Сервер проверяет hostname и `Tailscale-User-Login`, добавляемый Tailscale Serve. Разрешён только аккаунт владельца, полученный при настройке из Tailscale. Запросы на изменение запрещены сервером; доступные GET-маршруты перечислены явно. Доступ к произвольным файлам отсутствует. Интерфейс скрывает действия записи и оставляет просмотр записей, периодов, объектов и таблиц.
5. Конфигурация адреса и владельца — в игнорируемом `data/remote-access.json`. Личные записи, адрес сети, идентификаторы и снимки экрана в публичный Git не попадают. Tailscale Funnel и открытый доступ не используются.
6. Service worker хранит только экран отсутствия связи и его служебные файлы. Личные API-ответы и HTML дашборда не записываются в офлайн-кэш. При новой загрузке без ПК показывается «Нет соединения с ПК». Данные на уже открытой странице могут отражать последний успешный запрос до следующего обновления.
7. `Connect-Android.ps1` проверяет вход и существующий Serve, сохраняет конфигурацию, запускает Serve в фоне и включает скрытый автозапуск дашборда при входе пользователя Windows. Включение HTTPS может потребовать подтверждение владельца в Tailscale. Чужие настройки публикации скрипт не заменяет.

## Ограничения и эксплуатация

- ПК должен быть включён, иметь интернет и работать с запущенными дашбордом и Tailscale. Автозапуск срабатывает после входа в Windows, не до него; он не предотвращает сон и не включает выключенный ПК.
- Tailscale на Android использует VPN-подключение; одновременная работа с другим VPN зависит от настроек устройства. Вход, системное разрешение VPN и установка PWA требуют действий владельца.
- Постоянный адрес сохраняется пока сохраняются имя ПК и DNS-имя сети Tailscale. При их изменении настройка запускается повторно, старую установку может потребоваться заменить.
- HTTPS-сертификат содержит DNS-имя устройства и сети в публичном журнале сертификатов. Содержимое дашборда от этого публичным не становится.
- Дополнительные пользователи, автономная работа без ПК, редактор с телефона и перенос на постоянный внешний сервер — отдельные решения. Финансовое приложение здесь не изменяется.

## Проверка и оставшийся шаг

Проверено: 32/32 автоматических теста, включая отказ без конфигурации и нужного аккаунта, блокировку POST/PUT/PATCH/DELETE, отсутствие доступа к файлам и отсутствие личных API в кэше. В локальном предпросмотре проверены четыре раздела на ширине 320/360, заблокированные поля моделера и экран отсутствия связи после остановки тестового сервера. Проверка фактического доступа вне домашней Wi-Fi и установка на Android выполняются после входа владельца в Tailscale на обоих устройствах.
