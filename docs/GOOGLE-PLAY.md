# Google Play · Internal testing

Цель — установка и обновления полного Android-приложения через Google Play для выбранных тестировщиков. Windows и самостоятельный Focus & Norms имеют отдельные каналы распространения.

## Первая регистрация

1. Открыть [Play Console](https://play.google.com/console/signup) с личным Google-аккаунтом и включённой двухэтапной аутентификацией.
2. Выбрать тип **Personal**. Владелец указывает свои сведения, подтверждает личность, принимает соглашение и оплачивает разовый сбор $25. Проверить требования, показанные Google для конкретного аккаунта.
3. Подтвердить доступ к Android-устройству через Play Console, если Google это запросит.
4. Создать приложение **Indicators & Work Dashboard**, русский язык, тип App, бесплатное. Пакет закрепится после первого загруженного артефакта.
5. Выбрать **Test and release → Testing → Internal testing**. Добавить только согласованные Google-аккаунты. Не включать публичный Production или Open testing.

## Подпись и сохранение текущих данных

Сначала сверить SHA-256 сертификата установленного APK и настройку **Play App Signing**. Для обновления поверх существующей установки Google должен доставить совместимо подписанный APK. Загрузка AAB, подписанного прежним ключом, сама по себе этого не гарантирует: Google подписывает доставляемые APK своим выбранным app-signing key.

При первом подключении выбрать использование своего прежнего app-signing key. Если требуется PEPK, получить инструкцию и ключ шифрования именно из Play Console этого приложения. Перед передачей зашифрованного приватного ключа Google требуется отдельное подтверждение владельца. Исходный JKS хранить локально с резервной копией; не загружать его в GitHub и не помещать в артефакты.

После настройки при необходимости завести отдельный upload key, чтобы ключ загрузки и ключ подписи приложения имели разные назначения. Смена upload key не заменяет app-signing key.

## Сборка

Перед сборкой увеличить build number в `native-app/pubspec.yaml`. Для первой подготовленной сборки зарезервирован code **20**; далее использовать большее число. Для существующего локального toolchain из корня проекта:

```powershell
.\Build-Android.ps1 -Format AppBundle -KeyPropertiesPath $env:IW_ANDROID_KEY_PROPERTIES
```

`IW_ANDROID_KEY_PROPERTIES` должен заранее указывать на существующий приватный файл настроек подписи. Результат — `C:\IWD-Tools\iw-native-build\build\app\outputs\bundle\release\app-release.aab`. Проверить его через официальный [bundletool](https://github.com/google/bundletool/releases) и `Verify-AndroidBundle.ps1`; контрольную сумму, package, versionCode и сертификат сохранить в локальном журнале выпуска. Личные данные и ключи в AAB не включать.

## Первый выпуск

1. Создать release в Internal testing, загрузить проверенный AAB, добавить описание изменений.
2. Пройти обязательные пункты Console и проверить совместимость подписи. Не заявлять отсутствующие функции и не указывать тестовые/выдуманные личные сведения.
3. Опубликовать выпуск только для согласованного списка тестировщиков.
4. На телефоне открыть opt-in ссылку под добавленным Google-аккаунтом и присоединиться к тестированию. Открыть страницу приложения в Google Play, обновить/установить приложение, включить автообновления.
5. Сверить прежние заметки, нормативы, очередь и адрес своего сервера. Приложение не удалять для переустановки; при ошибке подписи сначала остановиться и проверить ключи.

## Дальнейшие обновления

Собрать новый AAB с увеличенным versionCode, проверить и выпустить в том же Internal testing. Участники получают обновления через Google Play; при необходимости можно нажать «Обновить» на странице приложения. Для проверки именно автоматической доставки выпустить следующий build и сверить номер версии после установки без USB.

Доступ к тестовому каналу не создаёт отдельные аккаунты данных в приложении. Для других людей нужен собственный сервер/архив до реализации многопользовательского доступа. Секреты сервера, Tailscale-адрес владельца и его локальные данные не включаются в сборку магазина.
