# ADR-005 · Закрытая веб-версия в Sites

С 2026-10-09 рабочий маршрут заменён [ADR-006](ADR-006-computer-host-and-timer.md): сервер на ПК и закрытый таймер через Tailscale. Этот ADR описывает сохранённую версию просмотра в Sites.

Дата: 2026-10-09. Решение владельца: «хотя можно пока в sites, если это позволяет sites». Заменяет текущий маршрут доступа из ADR-004; подготовленный вариант Tailscale остаётся в истории.

## Зачем

Получить простую постоянную ссылку на Indicators & Work Dashboard для просмотра из любого места, без включённого ПК и установки VPN. Добавить значок на главный экран Android. Поддержать собранность: быстро возвращаться к выбранным показателям, главной работе и объектам проектов. Снизить затраты на настройку доступа. Финансовое приложение Personal Throughput Accounting не меняется.

Владелец допускает аренду собственного сервера позже для регулярной работы по своим проектам. Сервер и срок пока не выбраны — No Data.

## Решение

1. Временно размещаем существующий интерфейс в **owner-private Sites**, под аккаунтом владельца. Доступ других людей и открытая публикация не выбраны. Сохраняем четыре раздела: Показатели, Проекты, Работа, Данные; отдельную страницу моделера, быстрые периоды, историю и источники.
2. Sites выполняет вход и политику доступа. Проверяем owner-private перед первой загрузкой личных данных и перед публикацией. Служебный bearer token получает агент через поддерживаемый Sites API, передаёт только данному Site в заголовке `OAI-Sites-Authorization`; не сохраняет его в файлах, браузере или исходниках. Dispatch проверяет и потребляет токен, не создавая браузерную identity.
3. Первая версия облака — **просмотр снимка**. Локальный редактор и исходные файлы остаются на ПК. Дата снимка видна на странице; автоматической синхронизации нет. Сегодня и календарные периоды рассчитываются в Asia/Tashkent по текущей дате, из записей снимка. Отсутствующие факты сохраняют No Data.
4. D1 хранит исходный UTF-8 текст шести файлов состояния и двух импортов: dashboard, workspace, indicators, daily-problems, daily-results, references, coda-snapshot, alpha-reference. Сохраняются ID, исходный текст, истории, даты и URL с якорями. Закрытый R2 хранит PNG-вложения. Личные данные передаются после публикации через runtime, никогда через Git, сборку или SQL-миграции.
5. Одно обновление загружает весь согласованный снимок и вложения, проверяет схемы, размеры и SHA-256. Неизменные версии сохраняются отдельно. Смена активной версии проверяет ожидаемый SHA и выполняется атомарно в D1; конфликт отклоняется. Старый снимок остаётся доступным до полного завершения загрузки.
6. Каждый GET создаёт собственное хранилище в памяти и использует существующие расчёты. Временные миграции и CSV, которые создают старые stores при чтении, не изменяют D1 или локальные файлы. Обычные POST/PUT/PATCH/DELETE запрещены сервером. Единственный служебный маршрут — обновление согласованного снимка; он опирается на подтверждённую закрытую политику Sites. Этот Site нельзя сделать публичным с данным shared updater.
7. PWA manifest, иконки и установка из Chrome остаются общими с локальной версией. Офлайн-кэш содержит только экран отсутствия сети. Личные HTML, API и вложения отдаются с no-store; показатели и записи офлайн не хранятся.

## Характеристики и ограничитель

| Характеристика | Ожидаемое изменение | Проверка |
| --- | --- | --- |
| Собранность | Выбранное важное доступно с телефона в момент возвращения к работе | Один реальный цикл: обзор → выбор работы → выполнение → обновлённый снимок |
| Доступность | Просмотр при выключенном ПК, из другой сети | Открыть HTTPS-ссылку на Android через мобильную сеть |
| Затратность поддержки | Не нужны VPN, постоянно включённый ПК и аренда VPS на первом этапе | Сколько времени занимает вход, установка значка и обновление снимка |
| Ограничитель приватности | Личные данные доступны только владельцу | Owner-private policy; отказ анонимному доступу; нет данных в исходниках и кэше |
| Ограничитель достоверности | Снимок не выдаётся за живые данные | Видна дата, явно указано отсутствие автоматической синхронизации |

Численные нормы для этих проверок владельцем не заданы — No Data. Установка на физическом Android и личная эксплуатационная проверка не выводятся из успешной сборки или тестов.

## Позже

Настроить действительно автоматический согласованный экспорт с ПК или выбрать облачное редактирование. После выбора собственного сервера переносить Node-приложение и JSON с проверкой историй, резервной копии, HTTPS и входа владельца. Облачный D1 snapshot использует тот же сырой формат файлов; отдельный финансовый модуль остаётся самостоятельным.
