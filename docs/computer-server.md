# Рабочая версия на ПК · 1.5.0

## Ежедневная работа

Открой **Открыть дашборд.cmd** или http://127.0.0.1:8787/#work. В «Работа → Фокус и время» нажми «Запустить таймер». Из карточки задачи, кейса, альфы или моделера кнопка «Таймер» сразу подставляет объект. Назови работу, выбери норматив или «Требует разбора», характер работы и режим. Можно менять длительности, ставить на паузу, добавлять пять минут и завершать досрочно. Завершение учитывает фактическое время; задача остаётся открытой до отдельной проверки результата.

В «Статистика недели и норматив конкретной работы» выбери объект и часы. План относится к показанной неделе. Пустое поле снимает его. Прогресс использует все записи, связанные с этим объектом. В «Данные → Сеансы таймера» доступны ID, настройки плана, факт и CSV. Для изменения назначения записи используй «Куда уходит время → Разобрать».

## Android из любой сети

1. Tailscale должен быть установлен на ПК и Android. Войди одним аккаунтом на обоих устройствах. На Android включи соединение Tailscale.
2. Запусти **Подключить Android.cmd** на ПК. Если запрошено включение HTTPS в Tailscale, выполни это действие в предложенной странице и повтори запуск. Скрипт не перезаписывает маршрут другого приложения и не включает открытый Funnel.
3. Открой выданный HTTPS-адрес в Chrome на Android. Меню → «Добавить на главный экран» / «Установить приложение». При соединении устройства видят общие данные и один общий активный таймер. ПК должен быть включён; после сна нужно дождаться восстановления соединения.
4. Для проверки запусти короткий сеанс на телефоне, открой ПК, поставь на паузу, обнови телефон. Затем заверши и проверь одну запись времени. Отдельно проверь сигнал с заблокированным экраном: он пока не гарантирован.

Без настроенной сети дашборд работает на самом ПК. Для работы без сети открой «Работа → Таймер на устройстве / Без сети» и один раз нажми «Сохранять на этом устройстве» при доступном сервере. После этого раздел открывается при выключенном ПК: сеансы и очередь сохраняются здесь. Завершённые записи отправляются при открытом приложении и доступном ПК автоматически или кнопкой «Синхронизировать». До подтверждения сервера норматив не меняется. При пересечении с таймером ПК запись требует разбора. Перед очисткой данных браузера сохрани локальную выгрузку. Остальные разделы требуют ПК. Подробности: [ADR-007](ADR-007-offline-device-timer.md).

## Сохранение и копии

Рабочие данные: `data/`; таймер, нормативы, проекты, альфы и записи времени — `data/dashboard.json`. Остальные модули сохраняют отдельные JSON и истории. Копии: `data/backups/`, список файлов и SHA256 — в `manifest.json`, последняя успешная копия — `latest.json`.

Сервер делает копию при старте, каждые 15 минут при изменениях и штатной остановке. Вручную: `node scripts/backup.mjs`. Для восстановления останови сервер, скопируй нужные файлы из выбранной копии обратно в `data/`, затем запусти дашборд. Существующий каталог сохрани отдельно перед восстановлением. Восстановление возвращает состояние на время копии; активный таймер потом потребует проверки факта. Копии не удаляются автоматически.

Автозапуск после входа Windows: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-Autostart.ps1`. Отключение — та же команда с `-Remove`. Это не запуск до входа пользователя и не отключение сна Windows.

## Перенос на арендованный сервер

Запусти `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Export-Server.ps1`. Приватный ZIP и распакованная копия появятся в `outputs/`. Архив содержит личные данные; в Git его не добавляй. В комплекте есть `transfer-manifest.json` с SHA256. Перед финальным переносом прекрати правки и останови старый сервер. Скопируй ZIP на новый сервер и распакуй в отдельный каталог приложения.

На Linux с уже установленным Docker Compose, из каталога приложения:

```sh
sudo chown -R 1000:1000 data
docker compose up -d --build
docker compose logs --tail=50 dashboard
curl --fail http://127.0.0.1:8787/api/health
```

Данные находятся в постоянном `./data`, контейнер перезапускается автоматически. Оба порта опубликованы только на `127.0.0.1` хоста; открывать их наружу не нужно. Docker-сборка и перезапуск на реальном Linux ещё требуют проверки.

Для закрытого адреса установи Tailscale по [официальной инструкции для Linux](https://tailscale.com/download/linux), выполни вход. На новом сервере надо создать новый `data/remote-access.json`: его URL и аккаунт получают из `tailscale status --json`; перенесённый конфиг ПК не подходит. Подготовлен скрипт `scripts/connect-server.mjs`, запускаемый Node.js 22 или новее на хосте из каталога приложения:

```sh
sudo tailscale up
node scripts/connect-server.mjs
```

Он проверяет, что устройство вошло как пользователь, сохраняет прежний конфиг, включает рабочий доступ только владельцу и направляет Serve на `127.0.0.1:8789`. Если Tailscale просит HTTPS, включи его в предложенной странице и повтори скрипт. После проверки нового адреса на телефоне отключи сервер старого ПК.
