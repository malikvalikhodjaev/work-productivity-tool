# ADR-012 · Приложение Windows и Android и дневные напоминания

Дата: 2026-10-14. Статус: реализация первой нативной версии 0.1.0.

## Назначение

Собранность остаётся главным предпочтением владельца: замечать важную проблему, регулярно моделировать системы, сверять выбранные индикаторы и видеть, куда уходит время. Продуктивность означает скорость и темп создания и изменения систем с нужными характеристиками. Время работы — один из источников наблюдений; оно само по себе не доказывает достижение результата. Численные ориентиры продуктивности, затратности поддержки и личный ограничитель остаются No Data до выбора владельца.

Нужны все пять разделов приложения, крупный таймер, звук в фоне, сохранение на устройстве без сети и дальнейшая отправка на сервер. Дневной норматив конкретной работы должен напоминать о себе каждый час.

## Решение

1. Клиент — Flutter и Dart для Windows и Android. Локальная база — SQLite с транзакциями, WAL и постоянным UUID устройства. Сервер Node и существующие JSON-файлы сохраняются по ADR-006/007. Нативное приложение не требует вкладки браузера; сервер нужен для синхронизации и общего таймера.
2. Доступны **Показатели**, **Проекты**, **Работа**, **Письмо**, **Данные**. Windows использует боковые кнопки, Android — нижнюю навигацию. Старый веб-интерфейс остаётся рабочим способом доступа к функциям, которые ещё не перенесены в нативный интерфейс.
3. На Windows закрытие окна оставляет приложение в трее. Крупный фокус можно закрепить поверх окон; локальный звук продолжает играть. Полный выход через меню трея прекращает звук и сигналы, сохраняя сеанс. Сон или выключение ПК не гарантируют своевременный сигнал.
   Уточнение 2026-10-15, клиент Windows 0.1.3: при активном сеансе сворачивание или закрытие основного окна автоматически показывает компактный таймер 430 × 430 поверх других окон. Это представление того же окна и репозитория, без второго таймера или отдельной очереди. Видны работа/проблема, отсчёт, минуты, пауза/продолжение, учёт и дневной чек-лист. «Все разделы» и нажатие на трей возвращают прежние размер, положение, развёрнутость и закрепление. «Скрыть таймер в трей» явно скрывает окно, сохраняя сеанс и звук. Настройка «Таймер при сворачивании» включена по умолчанию и сохраняется локально; без сеанса окно сворачивается обычным образом. Android продолжает использовать уведомление foreground service, а не это окно Windows.
4. Android использует foreground service для таймера и локального звука, системные уведомления и AlarmManager. Нужны разрешения уведомлений и точных будильников. Без разрешения точного будильника система может задержать сигнал. Принудительная остановка приложения пользователем прекращает фоновую работу до следующего запуска. Проверку на настоящем телефоне выполнять отдельно.
5. Общий таймер работает через существующее API сервера с revision, sessionId и неизменяемым requestId. До ответа команда сохранена локально. Потерянный ответ повторяется с тем же ID. Независимый таймер устройства включается явно; он не заменяет общий сеанс автоматически. Паузы исключены, помидорка ограничена планом, перерыв не создаёт рабочие минуты. При завершении рабочего сеанса можно уточнить минуты и записать наблюдение одной строкой.
6. Клиент сохраняет собственные правки карточек, целей, проектов, альф, проблем и эссе в SQLite и очереди. Это расширяет разрешённое локальное хранение ADR-007: на устройстве появляются снимки всех пяти разделов. Личные данные остаются на устройствах владельца и его сервере; в исходники GitHub не попадают.
7. Команды нативного API используют UUID объектов и квитанции, записанные атомарно вместе с изменением соответствующего JSON-файла. Повтор ID с другим содержимым запрещён. Устаревшая правка получает конфликт; исходник остаётся в очереди. Повторная отправка поверх свежей версии требует явного решения пользователя. Редактирование отправленной команды запрещено.
8. Очередь привязана к serverId установки. Другой сервер не получает накопленные записи автоматически. Для переноса на VPS нужны все личные файлы, serverId, квитанции и один пишущий процесс. Смена URL при сохранённом serverId допускается. Tailscale остаётся закрытым путём доступа; открытый порт, Funnel и публичное размещение личных данных не используются.
9. **Дневной норматив** хранит workRef, минуты, дни недели, время первого напоминания и признак включения. Повтор фиксирован: **60 минут**, с привязкой к выбранному первому времени и дню в Asia/Tashkent. Например, 09:30 → 10:30 → 11:30. «Скрыть» действует до следующего такого времени, после чего лист «Сделал это?» снова появляется. Выполненные нормы скрыты до следующего применимого дня. Общую настройку интервала можно добавить позже.
10. На Windows лист временно поднимает окно и после скрытия восстанавливает его прежнее состояние. На Android уведомление открывает список в приложении. Отметка «Сделал» хранится отдельно от минут и не создаёт запись времени. Подтверждённые интервалы таймера и ожидающие отправки локальные интервалы показываются с сохранением их происхождения.
11. APK подписывается постоянным приватным ключом владельца; ключ и пароль остаются вне Git. Обновления приложения должны сохранять этот ключ и идентификатор пакета. SQLite и очередь не удаляются при обычном обновлении. Перед удалением приложения, очисткой его данных или переносом устройства нужна локальная выгрузка и подтверждённая синхронизация.
12. Начиная с Native 0.1.5, ▶ «Фокус» на выбранной карточке/проблеме/нормативе сразу запускает выбранную работу с текущими настройками, без формы и кнопки «Сохранить». Для той же работы на паузе ▶ продолжает тот же ID; повтор для работающего сеанса ничего не дублирует. Другая активная работа не завершается автоматически. Длительность, помидорка/секундомер и общий/устройственный учёт выбираются отдельно в «Настройки таймера» и сохраняются на устройстве для следующих запусков. Общий учёт остаётся режимом по умолчанию; отсутствие связи не включает самостоятельный учёт автоматически. «Новая активность» требует назвать работу и имеет кнопку «Запустить». Команда общего запуска сохраняется до отправки; потеря ответа не заменяет UUID. Проверки [FP01–FP05](acceptance/23-focus-play.feature).

## Последствия

Уточнение 2026-10-15, Native 0.1.6: подтверждение общей команды восстанавливается при синхронизации и перед следующим действием. Потерянный ответ повторяет исходный UUID и тело; одновременные проверки объединяются. Перед отправкой проверяется serverId. Определённый отказ 400/409/422 вместе со свежим снимком освобождает очередь, сохраняя точную команду, наблюдение и причину в локальной истории «Данные → Отклонённые команды таймера». Сетевой сбой оставляет команду для повторной проверки. Устаревшая пауза/продолжение по явному нажатию может один раз повториться новым UUID только для того же активного sessionId; завершение, отмена и продление автоматически не повторяются с новой версией. Пауза не пишет факт и не прибавляет помидорки. В основном и компактном таймере видны статус ожидания и «Проверить действие»; отправка блокирует повторные кнопки до ответа. Старый снимок синхронизации не откатывает более новую revision. Проверки [TP01–TP05](acceptance/24-timer-pause-and-recovery.feature).

Один клиентский код уменьшает количество реализаций экранов; Windows и Android имеют разные механизмы фоновой работы. Сервер, очередь, клиент и платформенные службы всё равно требуют отдельных проверок. Первую версию нельзя считать полной заменой всех функций веб-интерфейса: история и восстановление публикаций, некоторые операции импорта и расширенные отчёты остаются в вебе.

Доступ супруги с собственным аккаунтом — отдельная следующая работа, описанная в [ADR-013](ADR-013-personal-accounts.md). Текущий сервер остаётся рассчитанным на одного владельца.

Ручная приёмка: [N01–N10](acceptance/18-native-client.feature). Основания механизмов: [Flutter platforms](https://docs.flutter.dev/reference/supported-platforms), [Android foreground services](https://developer.android.com/develop/background-work/services/fgs), [Android alarms](https://developer.android.com/develop/background-work/services/alarms/schedule).
