# ADR-015 · Telegram → входящие мысли → письмо

Дата: 2026-10-15. Статус: реализация 1.12.0, клиент 0.1.2.

## Зачем

Владелец хочет на ходу отправлять своему боту текст и голосовые, затем спокойно разбирать идеи и мысли в заметочнице. Предпочтение — собранность: мысль не теряется между телефоном и рабочим местом. Полученное сообщение само по себе не становится задачей, публикацией или результатом работы.

## Решение

1. Раздел «Письмо» содержит «Входящие мысли» с фильтрами «Не разобрано», «Разобрано», «Архив». Есть исходный текст, прослушивание голосового, тема, расшифровка / суть и свободные мысли при разборе. Архивирование обратимо. Кнопка «Создать черновик» переносит материал в существующий редактор эссе; публикация остаётся отдельным действием ADR-008.
2. Telegram Bot API получает исходящие HTTPS-запросы `getUpdates` от рабочего сервера. Публичный порт и webhook не нужны. Тот же процесс можно перенести с ПК на VPS; одновременно работает один получатель и один пишущий сервер. ПК нужен для получения, для отправки мысли из Telegram на телефоне Tailscale не требуется.
3. По Bot API непринятые обновления хранятся не более 24 часов. Выключенный на несколько дней ПК не обеспечивает сохранение всех сообщений. Голосовое скачивается с помощью `getFile`, стандартный предел — 20 MB. Превышение видно в карточке; исходное сообщение сохраняется. Сбой загрузки оставляет очередь аудио для повторной попытки.
4. Токен вводится в настройках веб-дашборда и хранится в игнорируемом `data/telegram-bot.json`. API статуса не возвращает его. Одноразовая ссылка `/start` действует 15 минут; её предъявление связывает приватный Telegram-аккаунт владельца. После привязки принимаются только сообщения этого отправителя в его личном чате. Группы и чужие аккаунты не принимаются. Существующий webhook другого бота не удаляется автоматически.
5. `data/inbox.json` хранит исходные обновления целиком, версии Telegram-сообщения, даты, разбор, историю и устойчивые ссылки. Ключ источника — bot ID + chat ID + message ID. Повтор update ID не добавляет запись или версию. Курсор подтверждения Telegram сохраняется вместе с источником атомарной заменой JSON. Перед следующей порцией сообщений их источник уже должен быть на диске.
6. Оригинальное аудио — `data/inbox-audio/`, имя по SHA-256, проверка байтов после записи. Курсор может двигаться после сохранения исходного сообщения; незагруженное аудио остаётся `pending`. Резервная копия включает JSON и аудио. Переносимый архив сервера содержит их и приватный конфиг; исходники Git не содержат личных сообщений, голосовых и токена.
7. Разбор защищён expectedUpdatedAt и UUID команды. Повтор UUID с другим содержимым отклоняется. Изменения источника не переписывают размышления владельца. Загрузка байтов аудио не меняет версию полей разбора. Просмотр не подтверждает выполнение работы.
8. Создание черновика затрагивает два JSON-файла: это восстановимая последовательность, не общая транзакция. Перед записью в архив фиксируется пакет конвертации со стабильными ID заметки и запроса. При сбое повтор исходной команды завершает связь с уже созданным черновиком; вторую заметку не создаёт и существующий текст редактора не перезаписывает.
9. В приложении входящие синхронизируются в SQLite; разбор без сети сохраняется в очереди нативного API по ADR-012. Аудио прослушивается при связи с сервером, оригинал находится на ПК / VPS. Браузер сохраняет незавершённый разбор в отдельной IndexedDB; конфликт оставляет текст на устройстве. Расшифровка в первой версии вводится владельцем при прослушивании, автоматическое распознавание речи не подключено.

## Приёмка и источники

[TI01–TI08](acceptance/20-telegram-inbox.feature), автоматические проверки `tests/inbox.test.mjs` и `tests/inbox-api.test.mjs`.

Официальные основания: [getUpdates](https://core.telegram.org/bots/api#getupdates), [getFile](https://core.telegram.org/bots/api#getfile), [создание бота](https://core.telegram.org/bots/tutorial#obtain-your-bot-token). Доставка настоящему боту, прослушивание на Redmi и выключение / возвращение ПК проверяются отдельно от моделируемого Telegram API.
