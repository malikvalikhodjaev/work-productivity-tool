# ADR-013 · Отдельные аккаунты владельца и супруги

Дата: 2026-10-14. Статус: требование сохранено; многопользовательская реализация ещё не начата.

## Запрос

Владелец хочет позже дать приложение супруге. У неё должен быть собственный аккаунт. Доступ с разных устройств и дальнейший перенос сервера должны сохраняться.

## Требования к следующей версии

- Один экземпляр приложения и сервера может обслуживать двух пользователей; у каждого свои задачи, кейсы, проекты, альфы, нормы, цели, эссе, финансовые записи и таймер.
- Сервер проверяет пользователя и право доступа в каждом API. Разделение экранов и выбора профиля недостаточно для защиты данных.
- Общий активный таймер означает один таймер **одного пользователя**, а не общий таймер всех людей.
- Локальная база, кэш, очередь, serverId и квитанции привязываются также к userId. Выход не отправляет чужую очередь; смена аккаунта не показывает личные записи предыдущего пользователя. Решение о сохранении локальной копии при выходе должно быть явным.
- Общие семейные проекты возможны только при выбранном доступе и проверяемых правах. По умолчанию личные записи закрыты.
- Миграция существующих данных присваивает их нынешнему владельцу, сохраняет ID, исходники, истории и резервную копию. Добавление супруги не копирует ей личные данные владельца.

## Что остаётся решить

Способ входа, приглашение супруги, восстановление доступа, серверное хранилище с userId, объём совместных проектов и правила синхронизации при переключении аккаунтов. Для этих вопросов пока No Data. Имена, пароль или аккаунт супруги автоматически не создаются.

До реализации и проверки разграничения доступа текущий сервер и нативная база используются одним владельцем. Tailscale ограничивает доступ к устройству, но сам по себе не заменяет аккаунты приложения.
