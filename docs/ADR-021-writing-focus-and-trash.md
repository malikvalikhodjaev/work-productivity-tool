# ADR-021 · Устойчивый ввод эссе и корзина в приложении

Статус: принято владельцем 2026-10-16.

## Запрос

В Windows при наборе эссе редактор терял фокус и требовал повторного клика. Владелец также попросил удаление записи.

## Решение

1. FocusNode и ScrollController редактора принадлежат состоянию WritingScreen. Перестроение экрана таймером раз в секунду, локальное сохранение и уведомления репозитория сохраняют объекты, курсор и подключение клавиатуры. Они освобождаются при закрытии раздела.
2. «Удалить запись» переносит эссе в обратимую корзину. Последний текст, тема, дата и состояние отправляются командой `saveAndTrash` в существующий API письма. Проверка версии, запись нового документа и перенос в корзину происходят одной атомарной заменой архива. Предыдущий документ остаётся в истории. Старые команды `trash` и `restore` сохраняют прежний смысл.
3. Новый локальный черновик тоже можно перенести в корзину без предварительного ручного сохранения. В SQLite сохраняется полный документ и неизменяемая команда. Список сразу учитывает локальную правку; отсутствие сети не скрывает её. После подтверждённой отправки действует серверная версия.
4. Корзина доступна в архиве «Письма». Удалённый текст можно просматривать; редактирование отключено. «Восстановить» возвращает ту же запись с тем же ID и последним текстом. Пока удаление ожидает ответа, восстановление отключено: оно не заменяет неподтверждённую команду.
5. Постоянное удаление не добавляется. Таймеры, личные записи и прежняя история не меняются миграциями. Исходники общие для Windows и Android; фактическая установка версии фиксируется отдельно.

## Проверка

[WE01–WE03](acceptance/29-writing-editor.feature). Регрессионный Flutter-тест воспроизводил потерю фокуса до исправления. Серверные тесты проверяют последний текст при удалении, историю, повтор команды, восстановление, конфликт версий и валидацию документа.
