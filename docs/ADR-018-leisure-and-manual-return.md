# ADR-018 · Leisure до выбранного времени

Дата: 2026-10-16. Статус: принято владельцем.

## Зачем

Собранность поддерживается явной границей отдыха и предложением вернуться к выбранной работе. Рабочие минуты и отдых имеют разные основания; отдых не выполняет часовые нормы и не создаёт помидорок.

## Решение

В рабочем таймере есть **Leisure**. Владелец выбирает день и время окончания в пределах ближайших 24 часов, по Ташкенту (UTC+5). Текущая работа остаётся той же: её интервалы закрываются, статус становится paused, остаток помидорки сохраняется. Доступны помидорка и секундомер; истёкшую помидорку сначала нужно учесть или продлить.

Достижение срока только предлагает **«Вернуться к работе?»**. **«Позже»** оставляет паузу. Рабочий отсчёт продолжается с фактического нажатия **«Вернуться к работе»**, включая досрочный возврат. Отложенное предложение не открывается каждую секунду: ключ сеанс + начало + срок сохраняется на устройстве; изменение срока создаёт новое напоминание. На веб-странице ключ действует до её перезагрузки. Устройства могут показать собственное предложение для общего сеанса; это не запускает дополнительный таймер.

При изменении срока начало отдыха сохраняется. Закрытый интервал содержит start, end и plannedUntil; текущий — start и until. Весь фактический отдых до нажатия, включая время после намеченного срока, остаётся Leisure. История действий содержит выбранный срок. Завершение работы во время отдыха закрывает оба вида интервалов, но учитывает только рабочие минуты. Отмена не добавляет факт и сохраняет историю.

Общий таймер сохраняет изменения атомарно в dashboard.json с revision и requestId. Неизменённый UUID безопасно повторяется после потерянного ответа. Нативный режим устройства сохраняет состояние в SQLite, браузерный — в IndexedDB; это по-прежнему явно выбранные независимые сеансы. Офлайн-импорт сохраняет исходник и интервалы отдыха, использует прежние проверки пересечений и постоянную квитанцию. Фоновая служба и overlay не записывают время самостоятельно.

Основной и компактный Windows-таймер, Android-плеер, уведомление и overlay показывают Leisure и его остаток. В Windows по сроку приложение показывает предложение возврата. Android использует существующую службу и системный будильник; при разрешённом уведомлении оно открывает подтверждение в приложении. Если точные будильники запрещены, используется системный неточный вариант: доставка может задержаться. Закрытая браузерная страница не обещает фоновое уведомление; при повторном открытии срок проверяется по сохранённым отметкам.

В недельной веб-статистике Leisure считается отдельно по пересечению интервалов с датами недели, без отменённых сеансов. Старые сеансы без Leisure читаются без миграции и без придуманных данных. В служебных данных доступны исходные интервалы.

## Проверка

`tests/leisure.test.mjs`: пауза и восстановление, ручной возврат, повтор UUID, неверный срок без изменения источника, правка срока, досрочное завершение и повтор офлайн-импорта. `native-app/test/leisure_test.dart`: сохранение доменной модели, форма, ручной возврат, однократное предложение и отсутствие автоматического запуска. Пользовательские сценарии: [L01–L06](acceptance/26-leisure.feature). Установка сборки не заменяет ручную проверку уведомления при заблокированном реальном телефоне.
