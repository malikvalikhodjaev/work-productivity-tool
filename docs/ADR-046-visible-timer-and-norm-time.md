# ADR-046: Таймер, который остаётся видимым

Дата: 2026-10-25. Основание: правки владельца после Windows 0.1.31. Клиент 0.1.32+34; сервер 1.25.0.

## Отображение

Windows использует скрытый системный заголовок и собственную прозрачную строку с переносом окна, разворачиванием двойным щелчком и кнопками окна. Она находится внутри того же фона, что и плеер. Основной дашборд сохраняет обычный светлый фон.

Часы располагаются по центру листа, отдельно от подписанных кнопок «Пауза / Продолжить» и «Учесть». Размер цифр — 96–112; остальные тексты не уменьшаются. Подписи «Главная проблема недели» и «Главная проблема на сегодня» показаны полностью над соответствующим текстом.

Белый чек-лист имеет естественную высоту. В большом окне три обычных норматива и пояснение лимита видны целиком. Когда содержимое не помещается, прокручивается весь лист; отдельного ограниченного по высоте списка нормативов в плеере нет. Количество нормативов не ограничивается и не сворачивается. Длинные формулировки проблем имеют собственную доступную прокрутку. Настройки находятся за кнопкой.

При возврате к общему дашборду под содержимым каждой вкладки остаётся панель текущего сеанса: отсчёт, работа, явная пауза/перерыв, продолжение, учёт и открытие крупного таймера. Панель использует тот же репозиторий и ID сеанса; отдельный процесс или второй таймер не создаются. Тики обновляют панель, а не редакторы и таблицы.

## Тип времени норматива

Поле `workType` принимает investment, productive, leisure, waste либо пустую строку «Как у карточки работы». Значение сохраняется локально и синхронизируется вместе с датированной версией норматива. Новый сеанс связанной работы получает явно выбранный тип действующего норматива; при пустом значении сохраняется тип карточки. Действующий сеанс и прежние записи не переклассифицируются. Неотмеченное время автоматически не становится Waste.

Сервер сохраняет поле, проверяет допустимые значения и включает прежнее значение в историю. Команда старого клиента без поля не стирает выбранный тип, в том числе при изменении нормы с будущей даты. Пустое поле, переданное явно, снимает переопределение.

## Закрепление Windows

Предыдущее исправление существующих `.lnk` дополняется настройкой нового закрепления. Процесс и окно получают стабильный AppUserModelID `UzIW.IndicatorsWork`; ярлыки получают тот же ID. Окно явно задаёт RelaunchCommand, RelaunchDisplayNameResource и RelaunchIconResource из локальной помидорки. Самостоятельная редакция имеет отдельный ID `UzIW.FocusNorms`.

Repair-NativeShortcuts.ps1 исправляет только точное приложение/его launcher, сохраняет резервную копию ярлыка, проверяет ID и иконку после записи. Глобальный кэш не удаляется, Explorer не перезапускается. Идентификатор архива и каталог SQLite не меняются.

Документация Windows: https://learn.microsoft.com/en-us/windows/win32/shell/appids и https://learn.microsoft.com/en-us/windows/win32/properties/props-system-appusermodel-relaunchiconresource.

## Проверки

Малое и широкое окно, естественная высота трёх нормативов, длинный список, кнопки с подписями, перенос проблем, единый сеанс при смене раздела и пауза. Тип норматива: локальная команда → новый сеанс → неизменность активного сеанса; серверный перезапуск, прежний клиент, будущая дата, проверка входа и сохранение старых фактов. Иконка: резервирование тестового ярлыка, чтение ID/ICO и повтор без изменений. Установка и подтверждение Windows проверяются отдельно после сохранения открытых текстов владельцем.
