# ADR-022 · Локальное сохранение и синхронизация приложения

Дата: 2026-10-16. Статус: принято по запросу владельца.

## Основание

Ожидание ответа общего таймера блокировало следующее действие при потере сети. Владелец требует сохранять данные на устройстве и выбрал автоматическую синхронизацию при доступном сервере. В «Данных» нужна явная кнопка и состояние отправки.

## Решение

1. В нативном приложении действие таймера сначала сохраняется в SQLite. Неизменяемая команда, время нажатия, ID будущего сеанса и полный локальный снимок записываются одной транзакцией. Пауза, продолжение, продление, Leisure, завершение и новый запуск работают без ожидания сети. Обычные карточки, разбор входящих и эссе используют прежние локальные черновики и очередь.
2. Общий таймер сохраняет тот же ID на устройстве и сервере. Сервер 1.16.0 объявляет поддержку отложенных команд. Команды отправляются последовательно, с исходными UUID, revision и временем действия. Сервер считает интервалы на момент нажатия, проверяет порядок событий, часы и уникальность ID. Повтор после потери ответа не создаёт второй факт. Старые веб-команды без этих полей сохраняют прежний смысл.
3. Локальный снимок имеет приоритет, пока команды не подтверждены. Снимок сервера не стирает его. Квитанция обновляет серверный кэш; локальная проекция удаляется после подтверждения всей очереди таймера. Завершённая полная помидорка видна с отметкой ожидания. Конфликтующая цепочка не увеличивает норматив.
4. Сохраняются проверки serverId и адреса до отправки и при смене адреса. Команды не отправляются другой установке. Конкурирующая правка другого устройства становится явным конфликтом; автоматического применения временной цепочки поверх чужой версии нет. Исходные команды и наблюдения остаются локально. Нельзя гарантировать одновременную согласованность нескольких отключённых устройств.
5. «Данные → Синхронизация» показывает очередь, конфликты, последнюю связь, черновики и кнопку. Автоматический режим включён по выбору владельца: попытка после изменения и каждые 30 секунд, пока приложение работает. Его можно отключить и отправлять вручную. Отсутствие связи не отменяет локальную запись. Полный выход/принудительная остановка не обещают фоновую отправку; очередь переживает следующий запуск.
6. Android-служба не заменяет таймер серверным снимком при неотправленных локальных изменениях и не опрашивает сервер при отключённой автоматической синхронизации. Малое окно показывает ту же локальную проекцию. Новая база и новые разрешения не требуются.
7. Старый слот `pendingTimer` сохраняется и проверяется исходным UUID. Неподтверждённые команды прежних версий не переписываются. Старые конфликтные события требуют разбора и остаются в истории. Явный независимый режим устройства из ADR-007 также сохраняется.

Это уточняет требование связи общего таймера из ADR-006/012. Первое подключение к своей установке по-прежнему нужно для идентификации архива и связей; после него работу можно сохранять при выключенном сервере.

## Проверки

[LS01–LS04](acceptance/30-local-save-and-notes.feature). Отдельно проверяются перезапуск SQLite, задержанный ответ, неизменный повтор, порядок событий, помидорки, другой сервер и конфликт revision. Пользовательская проверка настоящего Android без сети не заменяется тестами.
