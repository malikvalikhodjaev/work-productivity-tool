# ADR-020 · Библиотека сигналов таймера

Дата: 2026-10-16. Статус: принято по просьбе владельца; реализация 1.15.0 / Native 0.1.10.

## Зачем

Окончание интервала должно быть различимо среди других уведомлений. Владелец попросил приятные эстетичные сигналы, в том числе «бип-бип». Численная оценка слышимости не выбрана; окончательное предпочтение определяется прослушиванием на устройствах владельца.

## Решение

1. Шесть собственных коротких PCM WAV: Бип-бип, Сонар, Стекло, Маримба, Орбита, Тёплый колокол. Прежний сигнал сохранён седьмым вариантом. Исходный синтезатор — `scripts/generate-timer-ringtones.mjs`: плавные атака и затухание, запас до цифрового клиппинга, длительность до трёх секунд, без внешних записей и зависимостей от облака.
2. В таймере и настройках приложения доступна **Библиотека рингтонов**. Можно прослушать любой вариант, остановить прослушивание и выбрать сигнал. Прослушивание не запускает таймер, не меняет выбранный сигнал автоматически и не записывает минуты. Выбор и громкость хранятся на устройстве в SQLite, в вебе — в настройках этого браузера. Фоновые шумы имеют отдельную громкость и выбор.
3. Сигнал используется для окончания помидорки, перерыва и Leisure. Он однократный, без бесконечного повторения. Windows и открытое приложение Android используют встроенный WAV. Фоновое уведомление Android использует системный канал выбранной мелодии. У каждого варианта устойчивый ID канала; существующие настройки пользователя не переписываются. Часовые напоминания норм остаются в прежнем канале.
4. Системная громкость, отключение уведомлений, режим «Не беспокоить» и изменения канала остаются под управлением Android. Громкость библиотеки применяется к предпрослушиванию и звуку открытого приложения; в фоне действует громкость уведомлений. Из библиотеки можно открыть настройки выбранного канала Android. Приложение не обходит ограничения и не требует новых разрешений.
5. Сигналы доступны Android по устойчивым content URI, поскольку ресурсные ID могут меняться при обновлении. Read-only `TimerRingtoneProvider` разрешает только семь имён встроенных WAV, не принимает произвольные пути, отклоняет режим записи и все операции изменения. Другим приложениям доступны только эти общедоступные звуковые ассеты; личные файлы, база, экспорт и токены через этот provider недоступны. WAV копируются в отдельный внутренний каталог атомарно при первом чтении.
6. Android foreground и системный будильник используют общий ключ уже поданного сигнала, чтобы открытие приложения после фонового сигнала не воспроизводило его повторно. Служба и плеер не меняют состояние рабочего сеанса. В вебе браузер может потребовать предварительное действие для воспроизведения; кнопка «Прослушать» позволяет проверить звук. Закрытая страница не гарантирует сигнал, а нативный фон по-прежнему требует системных разрешений.

## Проверка и источники

Node-проверки читают фактические WAV, проверяют формат, запас амплитуды, различие вариантов и равенство файлов веба/приложения. Flutter-проверки проверяют безопасный выбор, независимость предпрослушивания от таймера и сохранение настроек. Пользовательская проверка: [RT01–RT04](acceptance/28-timer-ringtones.feature).

Основания Android: [управление каналами и настройки пользователя](https://developer.android.com/develop/ui/compose/notifications/channels), [NotificationChannel.setSound и устойчивость URI](https://developer.android.com/reference/android/app/NotificationChannel#setSound(android.net.Uri,%20android.media.AudioAttributes)). Звук при реальной блокировке телефона и субъективная различимость остаются пользовательской приёмкой.
