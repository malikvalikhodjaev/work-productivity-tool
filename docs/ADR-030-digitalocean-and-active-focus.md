# ADR-030 · Общий сервер DigitalOcean и понятный занятый таймер

Дата: 19.10.2026. Запрошено владельцем. Клиент 0.1.17, сервер 1.20.1.

## Занятый таймер

Одновременно работает один связанный сеанс. Play другой работы не завершает, не отменяет и не заменяет текущий, в том числе поставленный на паузу. Приложение называет работу и предлагает открыть текущий таймер. Для переключения владелец учитывает или отменяет прежний сеанс, затем нажимает Play нужной карточки. Повтор Play той же карточки сохраняет прежнюю логику продолжения паузы.

Веб и сервер также включают название работы в сообщение. Офлайн-команды остаются неизменяемыми и сохраняют время нажатия. При двух отключённых устройствах общая блокировка недоступна: возможное расхождение по-прежнему сохраняется для разбора, не исправляется автоматическим списанием времени.

## Перенос хоста

DigitalOcean становится единственным пишущим сервером; Windows и Android продолжают сначала сохранять изменения в SQLite и автоматически отправлять очередь при доступности сервера. Tailscale Serve и отдельный шлюз владельца сохраняются. Порты 8787/8789 остаются на loopback хоста; публичный доступ к данным и Funnel не включаются.

Начальная конфигурация: Basic Regular, 1 vCPU, 1 GiB RAM, 25 GiB SSD — $6/месяц по прайсу на дату решения. Регион выбирается в доступном кабинете до создания. Отдельная управляемая БД не требуется для текущего файлового хранилища. Резервные копии DigitalOcean оплачиваются дополнительно; выбор тарифа копий требует согласования, в исходники включено только существующее резервирование приложения.

### Порядок перехода

1. Подготовить VPS, SSH и Tailscale. До переноса данных сервер приложения на VPS не запускать.
2. Сохранить открытые тексты и отправить очереди Windows/Android старому серверу; проверить отсутствие неразобранных конфликтов. Снять копию локальной SQLite каждого устройства отдельно — серверный экспорт её не заменяет.
3. Остановить старый сервер и исключить его повторный автоматический запуск. После остановки выполнить `Export-Server.ps1 -FinalTransfer`. Пакет без этого флага — только `live-preview`, он не считается согласованным финальным снимком.
4. Передавать приватный пакет по SSH. Не загружать его в GitHub или публичный bucket. Ключ подписи Android `data/native-signing` и прежние резервные каталоги в серверный пакет не входят. Оригиналы на ПК сохраняются.
5. На VPS до первого запуска проверить `node scripts/verify-transfer.mjs . --final`: SHA256 каждого файла, отсутствие лишних/пропавших файлов, ID сервера и архива письма. Скрипт не изменяет исходные данные.
6. Создать конфиг доступа нового хоста через `node scripts/connect-server.mjs --provider digitalocean`. Он записывает новый адрес Tailscale и явно отмечает хостинг; прежний адрес ПК не копируется как рабочий адрес VPS.
7. Запустить один контейнер с постоянным каталогом `./data`. Проверить health, архив письма, нормативы, вложения, Telegram и сохранение после рестарта контейнера. Перевести оба клиента на новый HTTPS-адрес; ID архива должен остаться прежним. Не сбрасывать serverId клиента и не очищать очередь ради обхода ошибки.
8. На ПК выполнить `Activate-Remote-Server.ps1`, передав новый Url, ExpectedServerId и ExpectedWritingInstanceId из проверенного манифеста. Скрипт требует остановки прежнего сервера, сверяет новый сервер и записывает `data/server-moved.json`. После этого ярлык/автозагрузка не поднимают старый сервер; прямой запуск server.mjs также отказывается от записи. Адрес в клиентах меняется отдельно без очистки базы.
9. Проверить тестовую запись с телефона и её появление на Windows, затем паузу того же сеанса с обоих устройств без двойного факта. Проверить доступ с выключенным ПК. Только после этого считать переезд завершённым.

Для отката сначала остановить VPS. Если VPS уже принял записи, перед откатом нужен обратный согласованный экспорт его актуальных данных. Старый снимок на ПК нельзя запускать параллельно или выдавать за актуальный.

## Текущее состояние

20.10.2026 VPS создан и подключён к сети владельца. Ubuntu 24.04, Docker Compose и Tailscale установлены. Перед запуском проверен финальный пакет из 250 файлов; SHA-256 и идентификаторы архивов сохранены. Старый сервер на ПК остановлен и защищён маркером переноса. Новый сервер отвечает по закрытому HTTPS-адресу, порты опубликованы только на loopback.

После перезапуска контейнера контрольные суммы файлов письма, работ, справочников и дашборда совпали. Резервирование приложения и Telegram работают. Владелец подтвердил синхронизацию Android с новым адресом; создание новой записи с телефона пока не проверялось.

21.10.2026 владелец сохранил адрес штатным интерфейсом Windows и разрешил перезапуск. Проверка SQLite прошла: целостность и JSON корректны, идентификатор сервера прежний, очередь пуста. После установки 0.1.18 на отдельной копии SQLite/WAL подтверждены актуальная версия, успешная синхронизация с VPS и отсутствие ошибки связи. Прежние исходные файлы после ошибки целостности сохранены для диагностики; причина той ошибки не установлена. Сторонними SQLite-инструментами рабочую базу запущенного клиента не открывать.

Сервер обновлён до 1.21.0 с предварительной копией и проверкой неизменности данных. Полная пользовательская проверка «новая запись с телефона → Windows», управления одним сеансом с двух устройств и доступа при выключенном ПК ещё не выполнена. Адреса, ключи, идентификаторы и личные архивы остаются в приватных файлах установки.

[Runbook VPS](VPS-RUNBOOK.md) описывает размещение, запуск, копии и откат.

Проверки: FP03, `quick_focus_test.dart`, `timer.test.mjs`, `server-transfer.test.mjs`, `remote-view.test.mjs`.
