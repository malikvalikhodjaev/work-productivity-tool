# ADR-049 · Голосовые, статусы и проекты с моделями

Дата: 2026-10-26. Клиент 0.1.37+39, сервер 1.28.0. Запрос владельца после проверки 0.1.36.

## Голосовые Telegram

Клиент разрешает фактический маршрут `/api/inbox/<UUID>/audio` только на настроенном сервере. Служебный ключ не отправляется на другой origin; редиректы, посторонние query/fragment, HTML и пустые ответы не принимаются за аудио. Используется поле MIME `audio.mime`, а не отсутствующее `mimeType`. Пауза продолжает ту же запись; повторное прослушивание использует уже загруженные байты. Во время загрузки повторный Play недоступен; закрытый разбор не начинает воспроизведение после завершения запроса. Ошибки доступа, загрузки и декодирования различаются.

На реальной записи проверено: оригинал доступен через защищённый HTTPS, его OGG не декодируется штатным Windows Media Foundation на ПК владельца. Поэтому Windows запрашивает `?format=wav` на том же защищённом маршруте. Сервер через FFmpeg создаёт производную PCM WAV (mono, 16 kHz), оригинал не переписывает. Android получает исходный формат. Ключи доступа и правила шлюза сохраняются. FFmpeg входит в Docker-образ; при локальном запуске сервера требуется доступный `ffmpeg` или `FFMPEG_BINARY`.

Производная копия хранится в `inbox-playback-cache`, по хешу оригинала и версии формата. Повторные одновременные запросы одной записи используют одну операцию. Входной контейнер задан явно; протоколы ограничены `file,pipe`, внешние адреса не загружаются. Есть таймаут 30 секунд и предел 25 MiB; превышение возвращает ошибку, обрезанная запись не выдаётся за полную. Частичный служебный файл удаляется при сбое; исходник остаётся. Экспорт и история разбора не меняются.

## Чек-лист и цели

Фильтры типов времени находятся ниже чекбоксов и общего лимита: одна горизонтально прокручиваемая строка с нейтральными неактивными вариантами. Чекбоксы не сворачиваются. Состав типов, подсветка действующего норматива, состояние сеанса и общий дневной лимит не меняются от фильтра.

«Статус цели» — список непосредственно в ячейке и в подробностях. Значения согласованы со стадиями «Работы»: заметка, план, работа, ввод в эксплуатацию, готовность, эксплуатация, препятствие, выведено/отложено. Старые `paused` и `archived` поддерживаются без миграции и потери значения. Статус не подменяет числовой замер. Изменение сохраняет связь цели с работой, прежнюю версию и возможность отмены.

## Проекты и модели

Раздел называется «Проекты и модели». Сверху остаются «Мои проекты» со списком/доской. Далее явно отделено «Моделирование проектов (по альфам)»: общая таблица проектов, вложенных проектов, альф и подальф с раскрытием/сворачиванием. Вид выбранного проекта сохраняет прежние столбцы-конструктор, зоны, историю, шаблоны и переносы ветвей. Аналитика раскрыта; в общем виде считается по всем проектам.

Смешанное дерево — только проекция: составные ID строк не записываются в предметные данные, UUID и parentId проектов/альф не меняются. Описания и ссылки редактируются существующими командами ячеек с точными `before/value`, локальным черновиком и очередью. У альфы есть `modelUrl` и прежнее многострочное описание. Ссылка входит в историю и экспорт/импорт; старые архивы без поля принимаются. Разрешены HTTP/HTTPS без учётных данных, открытие — по отдельному нажатию. Сервер не получает содержимое ссылки и не строит автоматические предпросмотры.

Проверки исходников и моделируемых сценариев отделены от реального декодирования, сборки, установки и проверки звука на устройствах. Личные голосовые и ключи не входят в Git или публичные тестовые фикстуры.
