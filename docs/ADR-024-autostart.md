# ADR-024 · Автозапуск приложения

Дата: 2026-10-18. Владелец запросил автозапуск на ПК и телефоне.

## Windows

При входе владельца в Windows одна запись в пользовательской папке автозагрузки вызывает Start-Native.ps1: локальный сервер запускается при необходимости, затем открывается установленное приложение. Запуск до входа в учётную запись этой схемой не обеспечивается.

Start-Native.ps1 использует mutex на каталог установки и вызывает установленный Flutter runner. Runner владеет отдельным single-instance mutex: повторный вызов возвращает существующее окно из трея и завершает временный процесс. Второй постоянный экземпляр приложения не создаётся. Проверять только наличие процесса и пропускать вызов нельзя: в этом случае скрытое окно не открывается по ярлыку. Недоступность сервера допускает запуск клиента с локальными данными. Режим CheckOnly по-прежнему требует исправного сервера и не вызывает runner.

Install-Native.ps1 включает автозапуск по умолчанию; SkipAutostart его пропускает. Install-Autostart.ps1 -ServerOnly оставляет только сервер. -Remove удаляет только собственную запись. Прежняя запись копируется в outputs/autostart-backups перед изменением или удалением. Системные службы, чужая автозагрузка и права доступа не изменяются.

На рабочем ПК запись установлена; два повторных запуска сохранили один исходный процесс без перезапуска. Реальный вход после перезагрузки ещё требует пользовательской проверки.

19.10.2026 исправлен повторный запуск из ярлыка: прежде launcher пропускал вызов, когда приложение уже работало в трее. Проверка установленного клиента 0.1.16 через настоящий ярлык вернула скрытое окно; PID приложения и ID активного серверного сеанса остались прежними. Изменён launcher, пересборка и перезапуск Flutter для этого исправления не требуются. Проверка AS02 покрывает этот сценарий отдельно от входа в Windows.

## Android — следующий этап

До переключения задачи на моделер проверены существующий BOOT_COMPLETED receiver и ограничения Android. Сейчас receiver восстанавливает будильники; полноценное восстановление службы активного таймера после загрузки ещё не добавлено. Не объявлять эту часть установленной.

При продолжении нужно восстановить сохранённый таймер, не создавать новый сеанс и не сбрасывать интервалы. Запуск mediaPlayback из BOOT_COMPLETED запрещён для приложений, ориентированных на Android 15+; воспроизведение после загрузки требует отдельного действия владельца. Фоновый автозапуск и настройки батареи Redmi выдаёт сам владелец. Принудительная остановка и первое открытие после установки имеют отдельные ограничения ОС.

Источники: [ограничения фонового запуска](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start), [типы foreground service](https://developer.android.com/develop/background-work/services/fgs/service-types).
